What it does today

working, end to end

Accounts

Register, sign in, stay signed in across reloads and tabs.

Sessions rotate their tokens; presenting an old one ends every session on the account, which is what a stolen token looks like.

Upload

Drop in a real video. It uploads straight to storage, then a worker measures it, builds a preview copy, a thumbnail and a waveform.

Files up to 2 GB. Anything unreadable fails with a sentence the user can act on rather than an error code.

Editing

Cut, split, trim, move and duplicate clips across video, audio and text tracks. Snapping, multi-select, unlimited undo.

Every edit is undoable in one press — including a captions run that added 1,800 clips.

Saving

Autosave. Close the tab, come back, find exactly what you left.

Two tabs editing the same project is detected and handed to the user to resolve — nothing is silently overwritten.

Playback

A real compositor in the browser: frame-accurate scrubbing, colour grades applied live, captions drawn over the picture.

Verified on Chrome, Firefox, Edge and iOS Safari. macOS Safari is untested — nobody on the project has a Mac.

Captions

Transcribes speech into one editable clip per word, timed to the audio. English, French and Hindi.

Words the recogniser was unsure about are flagged for review. Runs on our own servers, so it costs nothing per use.

Smart trim

Finds silence, filler words, stutters and restarted sentences, at three strengths, and cuts them in one undoable step.

Suggestions only until applied — and one press of undo puts the clip back.

Colour

Reads the picture and recommends one of five graded looks with a strength, applied instantly in the preview.

The same grade files will be used by the export renderer, so what you see is what will come out.

Credits

Every AI tool is priced before you press the button, charged when it starts, and refunded automatically if it fails.

The four plans are seeded with real numbers. Taking payments is M6; the accounting underneath it is already built and audited nightly.

Run it

two commands

First time only

Installs both halves and generates the shared API types.

make setup

Needs Docker, Node and Python. make doctor says exactly what is missing and what to run for it.

Every time after

Starts the database, the queue, storage, the API, the worker and the app — in one window you can watch.

make watch

Then open localhost:3123. Ports are picked automatically if something else already holds them.

Stop it

Stops this project's servers and leaves everything else on the machine alone.

make watch-stop

Your work is already saved — there is no separate save step to remember.

Test it

automated, then by hand

The full gate

One command runs everything the build server runs: 433 tests, type checking on both halves, linting, and a check that the API contract and the app still agree. 

make check

Takes about two minutes. It is the gate before anything is pushed.

The five-minute walkthrough

What to do to see the current milestone actually working, in order:

  1. Create an account on the sign-in screen.
  2. Add a video with a bit of talking in it, and wait for it to say ready.
  3. Press Add to timeline, then click the clip.
  4. In the panel on the right, press Run under Captions — the price is on the button before you press it.
  5. Watch the progress bar; the words appear on the timeline, one clip each, in time with the speech.
  6. Click any word and retype it — correcting a misheard name is the point.
  7. Reload the page. The correction is still there.

This is the milestone's own closing condition, and it was verified in a real browser rather than only in tests.

A proposal on the table

scope decided · awaiting go-ahead

The editor was used rather than tested, and it turned up eight usability problems that nothing in the current plan is scheduled to fix. The only visual work in the eight milestones was a design charter in M3, and that settled colours, type and component states — it never covered how large a control should be, where it should sit, or whether a feature can be found at all.

The one that matters most: from the home page, the only way into the product leads to a page that still says “built in M3”. Anyone who does not already know the editor's address cannot reach it.

A forgotten stub rather than a design problem, and ten minutes to close.

The rest: the play button sits nowhere near the picture it plays, the toolbar is thin for a video editor, the two side panels do not have room for the tools Phase 2 will add, the adjustment sliders are oversized and cannot be typed into, timeline zoom felt imprecise, and the timeline itself reads as bolted on rather than composed.

The three open scope questions are now decided — keep the timeline's current mouse-wheel behaviour rather than change it; fold the two side panels into one icon rail plus a single properties panel, instead of two panels stacked with no shared idea of what belongs where; and ship manual controls only for what the renderer already implements, holding any new effect type for Phase 2 so the preview and the exported file can never disagree.

What is left is craft work — sizes, spacing, the rail's exact visuals — and one scheduling call: close the dead end and the timeline framing before M5, and group the rest after M6, once the export dialog and the pricing screens have added interface of their own. Full write-up in the project docs.

A ninth problem from the same session is already fixed: titles and captions could not be moved or resized on the timeline at all. That was a defect rather than a matter of taste, so it did not wait for this decision.

Open, honestly

carried forward, not hidden

Six items are open across the three milestones above 90%. None of them blocks the next milestone; each was a judgement call rather than an oversight.

  • macOS Safari is untested. Blocked on hardware, not on time — nobody on the project has a Mac. iOS Safari, the harder case, passes.
  • Two of three caption styles. Design work rather than engineering; inventing them in code would ship two nobody chose.
  • Font, size and colour controls for text. The data is already stored and typed — each one is a control to add, not a change of shape.
  • Test fixtures for the AI tools. Lets the interface be worked on without running real jobs. Convenience, not correctness.
  • Retry messaging when a job fails. The refund is automatic and already tested; what is missing is the sentence telling the user it happened.
  • Offline backup of unsaved edits. Deferred by design. Work is saved to the server continuously; this would only cover losing the network mid-edit.
